# OpenAI 分组读缓存扣除

管理员创建、编辑 OpenAI 分组时可设置 `cache_read_deduction_percent`：范围 0–100，最多两位小数，默认 0。单位是百分点：96.3% 的缓存命中率扣除 20 后为 76.3%。其他平台的配置归零。

## 用量口径

设总输入为 T、原始读缓存为 C、扣除值为 D：

```text
应计读缓存 = floor(max(0, C - T × D / 100))
普通输入 = max(0, T - 应计读缓存 - 缓存写入)
```

总输入、缓存写入、输出不因扣除改变。计算使用整数百分点精度，最后截断；图片缓存按原始构成同比例分摊，图片部分向下取整，文本部分承接余数。异常缓存数量先约束到有效输入范围。D=0 时不执行扣除。

HTTP JSON、SSE、Responses WebSocket 和 Messages 协议转换在最终客户端写出边界使用应计用量，上游解析及计费回调保留原始数据。流式累计用量从原始快照重算；缺少总输入的临时缓存明细暂不向客户端发送。WebSocket 每轮独立处理。

用户余额、订阅、API Key 额度和用户金额限额使用应计费用。上游账号额度与账号成本统计使用原始用量和既有账号定价、倍率。原始口径费用仍是按本系统价格计算的金额，不是上游账单回执。

## 追溯和权限

非零扣除配置的请求保存 `usage_logs.cache_read_adjustment`，包含：

- `version`：计算版本。
- `percent`：请求使用的配置快照。
- `raw` / `effective`：原始和应计用量，总输入均包含缓存。
- `upstream_cost`：原始用量计算的费用，未乘账号倍率。

管理员使用日志、导出及汇总可查看两种口径。结构化日志事件 `openai.cache_read_deduction` 使用 `audit.cache_read_deduction` 组件，允许由管理员 Ops 系统日志索引。日志写入遵守现有日志级别、采样和保留配置；账务追溯以数据库快照为准。

普通用户 DTO 不包含快照或分组扣除配置；错误详情也会裁剪原始 usage。共用表格默认不显示审计字段，仅管理员页面开启。管理员通过模型 API 调用时，也获得应计 usage。

## 升级与关闭

迁移 `247_group_cache_read_deduction.sql` 新增分组配置和可空的请求快照字段。鉴权快照版本同步升级，编辑分组继续使用既有缓存失效机制。历史账单不重算，历史快照为空；管理员汇总对无快照的旧记录沿用原有用量。

将配置改回 0 可停止后续请求的扣除，既有账单和快照保持不变。长连接沿用建立请求时的分组快照，重新连接后读取更新后的配置。Live 会话当前没有 Tokens 计费链路，本功能不改变其既有行为。
